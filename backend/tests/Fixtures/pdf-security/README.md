# PDF security fixtures (V1.5.4 research)

Both files here are synthetic. Neither contains any Konica Minolta content,
metadata, or security material - see
`docs/maintenance/V1.5.4_SECURED_PDF_COMPATIBILITY.md` for the research these
fixtures support.

## `unencrypted-baseline.pdf`

A hand-built, minimal, valid one-page PDF (703 bytes) containing exactly:

```
A3 Tracker PDF Security Fixture
Page 1
Error Code Example: C-0000
Fixture content only
```

Built the same way `MaintenanceDocumentExtractionTest::buildFixturePdf()`
already builds its test PDFs elsewhere in this repo: hand-written objects,
real xref table, real trailer - no generator tool involved.

## `encrypted-r4-aes128-empty-user-password.pdf`

The same content, encrypted with [`qpdf`](https://qpdf.sourceforge.io/) 12.4.1
(a **local research tool only** - never a Production runtime dependency; see
"No shell-dependent Production design" in the V1.5.4 doc) to reproduce the
real Konica Minolta document's exact Standard Security Handler profile, as
independently confirmed by `qpdf --show-encryption`, `pypdf`, and this
codebase's own new `PdfSecurityInspector`:

| Field | Value |
|---|---|
| `/Filter` | `/Standard` |
| `/V` | 4 |
| `/R` | 4 |
| Crypt filter (`/StmF` = `/StrF`) | `/StdCF`, `/CFM` = `/AESV2` (AES-128-CBC) |
| Key length | 128 bits |
| `/EncryptMetadata` | absent -> defaults to `true` |
| Empty user password | **valid** (opens with no password prompt) |
| `/P` (permissions) | `-1340` - matches the real document's permission bitmask exactly (extraction for "any purpose" denied, accessibility extraction allowed, full printing allowed, all modification denied) |

Generation command (fresh, synthetic owner password generated with
`openssl rand -base64 24`, used once and discarded - never recorded, never
reused from the real document, and unrelated to the real document's actual
owner password, which this project has never attempted to recover):

```bash
qpdf --allow-weak-crypto --encrypt "" "<fresh-random-owner-password>" 128 \
  --use-aes=y --force-V4 \
  --accessibility=y --extract=n --print=full --modify=none --annotate=n --form=n --assemble=n --modify-other=n \
  -- unencrypted-baseline.pdf encrypted-r4-aes128-empty-user-password.pdf
```

`--allow-weak-crypto` is qpdf's flag for permitting *any* non-AES-256 profile
to be generated at all (qpdf 11.7+ nudges toward AES-256 by default) - it is
not a statement about AES-128 itself, which remains an acceptable, spec-legal
Standard Security Handler configuration and is exactly what the real document
uses.

The fixture's own `/O` and `/U` values are freshly generated by qpdf from the
fresh owner password above and bear no relationship to the real document's
`/O`/`/U` values, which are never reproduced, referenced, or derived from
anywhere in this repository.

One structural difference from the real document, noted for completeness:
qpdf encodes `/O` and `/U` as PDF **hex strings** (`<28BF4E5E...>`), while the
real document's producer ("Antenna House PDF Output Library") encodes them as
PDF **literal strings** (`(\373\252\261...)`) - both are spec-valid ways to
write the same opaque byte value (ISO 32000-1 7.3.4). `PdfSecurityInspector`
is tested against both encodings for exactly this reason.
